# OpenMAIC v0.3 需求文档

## 1. 版本范围

`v0.3` 聚焦以下能力：

1. 课堂页教师端 / 学生端视图
2. 课堂生成接口与服务端课堂真值打通
3. 首页“最近课堂”同时展示本地课堂与服务端课堂
4. 课堂删除、导入导出命名和媒体完整性收口
5. 课堂内代码编辑器、代码运行结果页签与代码沙箱能力

## 2. 核心目标

### 2.0 核心保护原则

系统必须满足以下硬性原则：

1. 后续设计和代码实现不得改动本项目已有核心功能的既有行为语义
2. 新增能力只能以增量方式接入，不得以“顺手重构”为名改写现有核心链路
3. 已有核心功能至少包括：
   - 幻灯片播放
   - PPT 指示效果
   - 翻页
   - 互动白板
   - 笔记
   - 对话
   - 课堂操作
   - 课堂生成
   - 课程包导入导出
4. 若新增功能确实需要触碰上述链路，必须以兼容为前提，并在设计文档中单独说明影响面、回归风险和保护方案
5. 若无法证明兼容，不允许进入实现阶段

### 2.0.1 技术栈差异处理原则

系统必须满足以下语言与技术栈约束：

1. OpenMAIC 主项目继续保持 `TypeScript + React + Next.js + Node.js` 为主实现技术栈
2. `deer-flow` 中 `LocalSandboxProvider` 和 `AioSandboxProvider` 的参考实现属于 `Python` 后端能力
3. 为实现本需求，不得要求 OpenMAIC 现有前后端改写为 Python
4. 语言差异的处理方式必须是以下之一：
   - 在 OpenMAIC 内实现 TypeScript 侧同语义适配层
   - 通过独立 Python 沙箱服务进行协议级对接
   - 通过容器镜像、命令模板和工作目录约定复用其运行时能力
5. 不允许采用源码级直接复用 Python 模块的方式，把 `deer-flow` 包直接嵌入 OpenMAIC 运行时
6. 任何涉及语言差异处理的方案都必须明确：
   - 进程边界
   - 调用协议
   - 错误传播方式
   - 生命周期管理
   - 部署方式
7. `v0.3` 当前选定方案为：
   - 在 OpenMAIC 内实现 TypeScript 侧同语义适配层
8. 独立 Python 沙箱服务方案不作为 `v0.3` 当前默认交付路径，只保留为后续扩展备选

### 2.1 课堂页视图

系统必须支持：

1. 同一课堂以教师端或学生端方式访问
2. 教师端保留课堂操作能力
3. 学生端隐藏课堂操作能力，但保留播放、翻页、笔记、对话
4. 课堂页顶部提供教师端、学生端和复制学生端链接三项入口
5. 该入口组固定显示在页面顶部居中位置

### 2.2 课堂代码编辑器

系统必须支持：

1. 在课堂页增加“代码编辑器”入口，点击后激活右侧“代码运行”工作台
2. 代码编辑器入口按钮位于“互动白板”按钮右侧
3. 代码编辑器展示样式、层级和交互风格参照“互动白板”，但不再以弹框或弹层形式独立呈现
4. 用户可在代码编辑器中直接编写、运行、停止和重置代码
5. 代码编辑器至少支持：
   - 语言切换
   - 多文件编辑
   - 入口文件设置
   - 标准输入
   - 运行日志
6. 右侧“代码运行”工作台至少包含：
   - 紧凑顶部工具条
   - 可折叠文件导航区
   - 主编辑区
   - 运行结果与预览区
   - 可折叠标准输入与状态区
7. 顶部工具条至少提供：
   - 语言选择
   - 入口文件展示
   - 保存草稿
   - 运行
   - 停止
   - 重置
   - 关闭
8. 代码编辑与代码运行结果统一收敛到右侧“代码运行”工作台，并与“笔记”“对话”“课堂操作”位于同一右侧区域
9. 教师端右侧菜单顺序扩展为：
   - 笔记
   - 对话
   - 课堂操作
   - 代码运行
10. 学生端右侧菜单顺序扩展为：
   - 笔记
   - 对话
   - 代码运行
11. 用户切离“代码运行”工作台后不应中断当前运行任务
12. 小屏设备可以降级为最小编辑模式或只读结果模式，但不得破坏课堂页现有布局
13. 右侧工作台必须按窄栏场景重新设计，不允许直接复用此前面向宽弹框的铺满式布局

### 2.3 代码运行与沙箱

系统必须支持：

1. 代码编辑器中的代码可直接运行
2. 运行环境支持主流编程语言，至少按语言运行时模板扩展：
   - Python
   - JavaScript / TypeScript
   - Java
   - C / C++
   - Go
   - Rust
   - C#
   - PHP
   - Ruby
   - Kotlin
   - Swift
   - Scala
   - Shell
   - HTML / CSS / 前端 Web 预览
3. 沙箱执行模式参考 `D:\Workspace\deer-flow`：
   - `LocalSandboxProvider`
   - `AioSandboxProvider`
4. `LocalSandboxProvider` 用于受信任本地开发或单机调试
5. `AioSandboxProvider` 用于隔离容器执行，作为共享环境和生产环境推荐模式
6. 代码运行结果至少展示：
   - `stdout`
   - `stderr`
   - 退出码
   - 运行状态
   - Web 预览地址或 iframe 预览
   - 生成产物列表
7. 代码编辑草稿与运行会话不得直接写入课堂主 JSON 真值
8. 代码编辑状态默认按 `classroomId + sceneId + clientSessionId` 作用域隔离，避免不同浏览器互相覆盖
9. 若复用 `deer-flow` 能力，必须通过适配层或独立服务方式接入，不能让 TypeScript 代码直接依赖 Python 包实现
10. `v0.3` 实现阶段应优先落地：
   - `local` 的 TypeScript provider
   - `aio` 的 TypeScript provider
11. 这两个 provider 可以复用 `deer-flow` 的语义、镜像和部署思路，但不依赖其 Python 业务运行时

### 2.3.1 代码工作台界面原则补充

右侧“代码工作台”界面必须遵守以下新增原则：

1. 界面目标以“简洁、实用、编辑优先”为主，不追求 IDE 式重装饰或过多信息卡片。
2. 代码编辑区必须是页面中的主区域，默认占据右侧工作台的大部分可见高度。
3. 编辑区必须支持纵向滚动，确保长代码在右侧窄栏中仍可持续编辑和阅读。
4. 默认界面只保留必要操作：
   - 语言选择
   - 入口文件选择
   - 保存
   - 运行
   - 停止
5. 非高频功能不得常驻主工具条；`stdin`、文件列表、结果明细等应采用折叠、抽屉或次级区方式呈现。
6. 结果区必须保留，但视觉优先级低于编辑区；未运行时不得抢占主要空间。
7. 文件导航必须轻量化，不允许占用类似桌面 IDE 左侧栏的大块固定宽度。
8. 不再要求在右侧工作台中同时固定展示“大量状态卡片、说明文案、装饰元素、次要统计信息”。
9. 在常见右侧窄栏宽度下，用户进入工作台后的第一视觉焦点必须是代码内容，而不是外围控制区。
10. 页面滚动设计必须明确：
   - 整个工作台允许纵向滚动
   - 编辑区自身也允许独立纵向滚动
   - 不允许出现编辑区高度被压缩到难以连续阅读的布局

### 2.4 课堂生成接口

系统必须支持：

1. `POST /api/generate-classroom` 创建后台生成任务
2. 创建响应立即返回 `jobId` 和 `classroomId`
3. `GET /api/generate-classroom/:jobId` 查询任务状态
4. 生成完成后课堂可直接被前端页面正常打开
5. 接口生成与前端生成页保持同一生成策略

具体要求：

1. 接口必须支持 `type = course | knowledge`
2. 生成任务要保留调用方传入的模型、图片、视频、TTS 配置
3. 后台 runner 不得忽略这些配置并退回服务器默认模型
4. 服务端生成出的 `stage.name`、`stage.style` 与前端生成页保持一致
5. 自动生成的角色信息需要持久化并在前端恢复

### 2.5 首页课堂列表

系统必须支持：

1. 首页“最近课堂”展示本地课堂
2. 首页“最近课堂”同时展示服务端已持久化课堂
3. 对于通过 `curl` 或后端接口生成的课堂，生成完成后刷新首页必须可见
4. 用户点击课堂卡片后可以进入教师端课堂页面

### 2.6 课堂删除与课程包

系统必须支持：

1. `DELETE /api/classroom/:id` 删除服务端课堂真值
2. 首页删除成功后同步清理本地缓存
3. 导出文件名统一为 `{classroomId}.omaic-course.zip`
4. 导出前自动保存当前课堂
5. 导出包内图片、音频、视频等媒体完整可回放

## 3. 验收标准

### 3.1 课堂页

1. `/classroom/{id}?view=teacher` 可见课堂操作
2. `/classroom/{id}?view=student` 不可见课堂操作
3. 页面顶部居中可见教师端、学生端、复制学生端链接
4. 代码编辑器按钮显示在互动白板按钮右侧
5. 点击代码编辑器按钮后，右侧自动切换到“代码运行”工作台并进入编辑态
6. 右侧区域可见“代码运行”页签
7. “代码运行”工作台内可见顶部工具条、左侧文件区和中央编辑区
8. 用户切到其他右侧页签后再次回到“代码运行”工作台，可恢复当前场景的工作状态

### 3.1.1 代码工作台界面验收补充

针对右侧“代码工作台”界面，本版本新增以下验收要求：

1. 用户打开工作台后，首屏主要看到的是代码编辑区，而不是状态摘要区或装饰区域。
2. 在长代码场景下，编辑区支持稳定上下滚动。
3. 文件区、结果区和 `stdin` 区必须是轻量或折叠式交互，不得默认占据大面积固定空间。
4. 运行前后界面都必须保持“编辑优先”，不允许自动演变为信息卡片优先的布局。

### 3.2 代码编辑器与沙箱

1. 在代码编辑器中输入示例代码后可直接运行
2. 运行中的日志、退出码和状态可在“代码运行”页签查看
3. HTML / 前端类项目可在结果区看到预览
4. 教师端和学生端分别有独立会话，不互相覆盖
5. 在 `LocalSandboxProvider` 模式下可完成本地受信任调试
6. 在 `AioSandboxProvider` 模式下可完成容器隔离执行
7. 执行中切离“代码运行”工作台后，执行结果仍持续更新
8. 页面刷新后，若执行仍在进行，前端可恢复查询与展示

### 3.3 课堂生成

1. `POST /api/generate-classroom` 返回 `classroomId`
2. 轮询成功态返回同一 `classroomId`
3. 任务完成后 `GET /api/classroom?id={classroomId}` 可读取课堂
4. 首页刷新后能看到该课堂
5. 点击课堂卡片能进入课堂

### 3.4 课程包

1. 导出文件名符合 `{classroomId}.omaic-course.zip`
2. 导出包重新导入后图片、音频、视频等媒体完整

## 4. 非目标

`v0.3` 不包含：

1. 完整 RBAC 鉴权体系
2. 课堂级协同代码编辑
3. 代码运行结果反向写回课件页面结构
4. 任意第三方依赖的无限制联网安装
