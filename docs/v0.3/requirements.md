# OpenMAIC v0.3 需求文档

## 1. 版本范围

`v0.3` 包含两项核心能力：

1. 将课堂页面区分为教师端和学生端
2. 提供“课堂生成”和“课堂删除”API 接口及文档
3. 统一课堂导入、导出文件名为 `classroomId`

本版本不包含：

1. 完整的登录、鉴权、RBAC 权限体系
2. 教师端与学生端的内容差异化编排
3. 批量删除课堂
4. 回收站、软删除或延迟恢复机制
5. 共享知识库、共享记忆等跨资源级联删除

## 2. 背景

`v0.2` 已完成：

1. 课堂持久化与课堂详情页加载
2. 课堂操作面板，包括保存、快照、导出、重制和编辑态切换
3. 课堂生成后台任务及轮询接口
4. 课程导入导出、版本快照和提示词重制

当前仍存在三类明显缺口：

1. 课堂页目前默认面向“教师使用场景”，学生进入同一页面时仍会看到“课堂操作”入口
2. 外部系统虽可通过现有生成任务接口轮询课堂生成状态，但缺少在 `v0.3` 语义下稳定、清晰的接口文档约束
3. 首页当前删除更多偏本地缓存清理，尚未形成“服务端课堂真值 + 关联资源真实删除”的统一 API 契约
4. 课堂导入、导出文件名当前仍可能使用课程标题等易变字段，不利于自动化集成、回传和稳定归档

## 3. 需求目标

### 3.1 教师端与学生端页面区分

系统需要支持：

1. 同一课堂数据可按教师端或学生端两种视图打开
2. 教师端保留当前 `v0.2` 的“课堂操作”能力
3. 学生端移除“课堂操作”入口和其下所有可变更课堂内容的操作
4. 除“课堂操作”外，学生端与教师端保持一致的课堂播放、页面导航、笔记、对话和课堂内容浏览体验
5. 保持现有课堂链接的兼容性，避免 `v0.2` 已有教师端使用方式失效

### 3.2 课堂生成与课堂删除 API 对外化

系统需要支持：

1. 为课堂生成提供稳定、可文档化的接口
2. 调用方在课堂生成成功后，可直接从 API 响应中获得 `classroomId`
3. 为课堂删除提供稳定、可文档化的接口
4. 课堂删除接口在成功时返回明确状态
5. 课堂删除必须真实删除课堂内容，而不是只从前端列表中移除

### 3.3 课堂导入导出文件命名统一

系统需要支持：

1. 课堂导出文件名统一以 `classroomId` 命名
2. 课堂导入流程中，导入包的主文件名应兼容以 `classroomId` 命名的标准文件
3. 文件名命名规则不受课堂标题修改影响
4. 文件名规则应在文档中固定，供自动化系统和人工操作统一使用

## 4. 功能需求

### 4.1 课堂页角色区分

系统必须支持：

1. 为课堂页提供明确的访问视图标识，用于区分教师端和学生端
2. 访问视图缺省值应为教师端，以兼容现有课堂链接和现有操作习惯
3. 教师端继续显示：
   - 课堂操作页签或入口
   - 保存草稿
   - 发布
   - 快照
   - 导出
   - 提示词重制
   - 编辑当前页 / 返回播放态
4. 学生端不得显示：
   - 课堂操作页签或入口
   - 课堂编辑、保存、发布、导出、重制等入口
5. 学生端必须继续支持：
   - 课堂播放与讲解
   - 左侧页面导航
   - 笔记
   - 对话
   - 课堂内容查看
6. 教师端与学生端必须读取同一份课堂数据真值，不得生成两份课堂副本
7. 从教师端切换到学生端后，当前课堂页码、课堂内容和展示顺序应保持一致
8. 角色区分应优先作为“视图层区分”交付；若当前版本未接入真实身份系统，不将其定义为完整权限系统

### 4.2 教师端 / 学生端访问约定

系统必须支持以下稳定约定之一，并在文档中固定下来：

1. 通过课堂页路由参数区分，例如 `/classroom/{id}?view=teacher|student`
2. 或通过独立路径区分，例如 `/classroom/{id}` 与 `/classroom/{id}/student`

约束要求：

1. 缺省访问必须落到教师端
2. 学生端访问方式必须稳定、可分享、可嵌入外部系统
3. 无效视图值必须有明确处理策略：
   - 归一化到教师端，或
   - 返回明确错误提示
4. 最终实现采用哪一种路由形式，需要在交付文档中固定，避免前后端约定不一致

### 4.3 课堂生成 API

系统必须支持：

1. 提供正式的“课堂生成”接口文档，覆盖请求体、返回体、错误码和轮询方式
2. 若生成采用异步任务模式，则创建任务接口可返回 `jobId`，但任务成功态响应中必须返回 `classroomId`
3. 生成成功后返回的 `classroomId` 必须可直接用于打开课堂详情页
4. 生成成功后响应中应同时返回课堂访问地址 `url`
5. 调用方无需依赖前端页面跳转或解析浏览器地址栏，即可获得 `classroomId`
6. 文档中必须明确课堂生成的最小请求参数和常用可选参数
7. 文档中必须明确生成失败时的错误返回格式

### 4.4 课堂删除 API

系统必须支持：

1. 提供正式的“课堂删除”接口文档，覆盖请求路径、成功响应、错误响应和删除范围
2. 课堂删除成功时返回明确状态，例如 `deleted`
3. 删除后再次读取该课堂时，服务端接口必须返回“课堂不存在”
4. 删除操作必须真实删除服务端课堂内容，包括至少：
   - 课堂主数据
   - 场景结构数据
   - 课堂媒体目录
   - 课堂音频目录
   - 课堂快照 / 修订记录
   - 与该课堂直接关联的重制预览或草稿数据
5. 删除操作不得误删共享资源，包括：
   - 知识库实体
   - 记忆实体
   - 其它课堂数据
6. 若前端首页调用课堂删除 API，则删除成功后应同步清理本地缓存，避免已删除课堂仍在本地列表残留
7. 删除失败时必须返回明确错误原因

### 4.5 API 文档交付要求

文档必须包含：

1. 接口名称、路径、方法
2. 请求参数说明
3. 成功响应示例
4. 失败响应示例
5. 字段含义说明
6. 删除范围说明
7. 与现有 `v0.2` 行为的兼容策略说明

### 4.6 课堂导入导出文件名规范

系统必须支持：

1. 课堂导出文件名使用 `classroomId` 作为主文件名
2. 推荐导出文件名格式为：
   - `{classroomId}.omaic-course.zip`
3. 若同时存在压缩包内 `manifest`，其中 `courseId` 或等价字段必须与文件名中的 `classroomId` 保持一致
4. 课堂标题、描述、语言等元信息变更后，导出文件名不得变化，除非 `classroomId` 本身发生变化
5. 导入接口不得依赖课堂标题推断目标文件名，应以包内元数据和 `classroomId` 作为识别主键
6. 导入成功后，若系统需要保留原始上传文件名用于审计，可单独记录，但业务展示和标准文档应以 `classroomId` 命名规则为准

## 5. 非功能需求

### 5.1 兼容性

1. 现有教师端课堂链接在 `v0.3` 发布后必须继续可用
2. 现有课堂生成任务接口若保留异步设计，不应破坏 `v0.2` 既有轮询链路
3. `v0.2` 已保存的课堂数据不应因教师端 / 学生端区分而失效

### 5.2 一致性

1. 教师端与学生端展示的课堂内容必须基于同一课堂真值
2. 学生端只隐藏“课堂操作”能力，不允许私自删减课堂内容、讲解流程、笔记或对话能力
3. API 文档中的字段命名必须与真实接口实现保持一致
4. 导入、导出文件名规则必须与 `classroomId` 保持一致，不得随课堂标题变化漂移

### 5.3 可恢复性与安全性

1. 删除课堂前应具备显式确认机制，避免误删
2. 删除失败不能导致课堂处于“部分删除、部分残留”的不一致状态
3. 删除共享资源边界必须清晰，避免删除课堂时误删知识库或记忆原始数据

### 5.4 可观测性

1. 课堂生成日志必须包含 `jobId`、状态、阶段和最终 `classroomId`
2. 课堂删除日志必须包含 `classroomId`、删除结果、失败原因和删除范围摘要
3. 若学生端访问被归一化或被拒绝，系统应有可追踪日志

## 6. 验收标准

### 6.1 教师端 / 学生端课堂页

满足以下条件视为通过：

1. 同一课堂可分别以教师端和学生端方式访问
2. 教师端能看到“课堂操作”并继续使用保存、导出、重制、编辑等能力
3. 学生端看不到“课堂操作”入口，也无法通过页面 UI 触达课堂编辑能力
4. 学生端仍可正常播放课堂、切换页面、查看笔记和使用对话
5. 教师端和学生端看到的课堂内容、顺序和讲解结果一致
6. 现有教师端课堂链接无需迁移即可继续使用

### 6.2 课堂生成 API

满足以下条件视为通过：

1. 有正式 API 文档，可供第三方集成阅读
2. 调用课堂生成接口后，可通过 API 响应获得 `classroomId`
3. 返回的 `classroomId` 可直接拼接为课堂访问链接并打开成功
4. 文档中包含最小请求示例、成功示例和失败示例

### 6.3 课堂删除 API

满足以下条件视为通过：

1. 有正式 API 文档，可供第三方集成阅读
2. 删除成功响应包含明确状态
3. 删除成功后再次调用课堂查询接口返回 404 或等价的“课堂不存在”
4. 删除成功后服务端课堂主数据和关联课堂资源已真实移除
5. 删除操作不会删除共享知识库和记忆数据
6. 若从首页触发删除，刷新后首页列表不再出现已删除课堂

### 6.4 课堂导入导出文件命名

满足以下条件视为通过：

1. 任意课堂导出时，下载文件名符合 `{classroomId}.omaic-course.zip`
2. 同一课堂即使修改标题后再次导出，文件名仍保持基于 `classroomId`
3. 导入接口可正确接收并处理以 `classroomId` 命名的标准课程包
4. 导出包文件名与包内 `manifest` 的课程标识保持一致

## 7. 实施优先级

### P0

1. 课堂页教师端 / 学生端区分
2. 学生端隐藏“课堂操作”及其所有入口
3. 课堂删除 API
4. 课堂生成 API 文档
5. 课堂删除 API 文档

### P1

1. 首页删除动作改为统一调用服务端课堂删除 API
2. 教师端 / 学生端访问约定在 README 或产品文档中对外说明
3. 删除后的本地缓存清理与列表刷新
4. 课堂导入、导出文件名统一为 `classroomId`

### P2

1. 学生端访问方式的外部分享、嵌入和短链规范
2. 后续与真实身份认证系统对接
