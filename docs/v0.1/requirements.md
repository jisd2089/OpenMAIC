# OpenMAIC v0.1 版本需求文档

## 1. 文档目的

本文档定义 OpenMAIC `v0.1` 版本的待交付需求，覆盖以下三类核心能力：

1. PPT 正文排版问题修复
2. 新增知识库能力
3. 新增记忆能力
4. 知识库支持视频导入，并在生成的 PPT 中嵌入知识库视频

本文档面向产品、研发、测试，作为 `v0.1` 的统一需求基线。

## 2. 版本目标

`v0.1` 的目标不是做成完整的企业知识平台，而是优先解决当前最影响使用的问题，并建立后续可扩展的知识增强教学基础设施。

本版本的交付目标如下：

- 恢复 PPT 导出的基本可读性，尤其是正文内容
- 让课程生成具备“从外部知识资产取材”的能力
- 让系统具备“可存、可检索、可复用”的记忆机制
- 让视频不再只来源于 AI 生成，也能来源于用户导入的知识库资产

## 3. 范围说明

### 3.1 在范围内

- PPT 正文排版修复
- 知识库集合管理
- 知识库文件导入
- 知识库文本检索
- 记忆的增删改查与检索
- 课程生成链路接入知识库和记忆
- 知识库视频导入、预览、引用与 PPT 嵌入

### 3.2 不在范围内

- 企业级权限中心
- 多组织、多租户协作管理
- 知识库工作流审批
- 自动跨页排版引擎
- 完整的长期记忆推理系统
- 视频自动摘要、镜头检测、字幕精修等高级处理

## 4. 当前现状与问题

### 4.1 PPT 正文排版问题

当前 PPT 导出中，标题位置通常较准确，但正文排版明显失控，主要表现为：

- 正文文本框高度估算不准
- 多段正文、bullet 列表排版混乱
- 文本框向页面底部方向溢出
- 页面内其他元素不会随正文重排，最终遮挡或超出可视区域

### 4.2 知识库能力缺失

当前 OpenMAIC 生成课程主要依赖：

- 用户输入主题
- PDF 解析结果
- AI 生成图片/视频

系统缺少可长期沉淀、可反复复用的知识库层，因此存在以下问题：

- 同一领域资料无法积累复用
- 无法对生成结果施加稳定的知识约束
- 视频、图片、文档等教学资产无法形成统一资源池

### 4.3 记忆能力缺失

当前系统没有独立的“记忆”模块：

- 无法保存高价值结论、偏好、教学规则、常用模板
- 无法跨课堂复用用户长期偏好
- 无法把课堂生成中的关键内容沉淀为可检索资产

### 4.4 视频能力的现状辨析

OpenMAIC 当前已经具备：

- AI 生成视频能力
- 画布中的 `video` 元素能力
- PPT 导出中的 `addMedia` 视频嵌入能力

因此 `v0.1` 新增需求不应表述为“从零支持视频嵌入 PPT”，而应表述为：

- 支持将用户导入到知识库中的视频作为合法教学资产
- 支持在课程生成和 PPT 导出中引用知识库视频

## 6. 需求一：PPT 正文排版修复

### 6.1 问题根因

根据现有代码分析，正文排版问题主要来自以下链路叠加：

1. 文本高度由提示词和固定查表估算，正文高度常被低估
2. 编辑器有自动测高能力，但导出阶段不会重新测量
3. 导出设置 `autoFit: true`，PowerPoint 会自动向下扩张文本框
4. 列表正文使用 `<p>• 文本</p>` 这种非标准 bullet 语义，导出后缩进混乱
5. 编辑器与导出端的 line-height、paragraph spacing、文本度量口径不一致

### 6.2 需求目标

- 正文不得再向页面底部大面积溢出
- 常见 bullet 列表导出后必须可读
- 导出结果应尽量接近编辑器可见排版
- 标题与其他元素不得因修复产生明显回归

### 6.3 需求项

#### 6.3.1 禁止正文依赖 PowerPoint 自动下扩文本框

要求：

- 调整当前 PPT 文本导出策略
- 移除或替换会触发正文下扩的自动适配行为
- 文本框高度必须由系统显式控制

#### 6.3.2 导出前重新测量正文真实高度

要求：

- 对每个正文文本元素执行导出前真实测量
- 测量逻辑尽量与编辑器一致
- 若文本高度不足，导出前自动修正

#### 6.3.3 增加正文溢出保护机制

要求：

- 导出前检测文本底边是否超出安全区域
- 当正文超出剩余空间时，至少支持一种保底策略：
  - 缩字
  - 裁剪并告警
  - 阻止导出并提示用户

#### 6.3.4 统一 bullet 语义

要求：

- 生成侧优先使用标准 `ul/ol/li`
- 导出侧按标准列表生成 PPT bullet
- 对历史内容中的 `•` 字符段落做兼容处理

#### 6.3.5 统一文本度量口径

要求：

- 统一 padding、line-height、paragraph spacing、bullet indentation 的计算方式
- 降低“编辑器里正常、导出后失真”的概率

### 6.4 验收标准

- 单页 3-5 条 bullet 正文不溢出页面底部
- 2-4 段正文能完整显示
- 标题 + 正文 + 图片混排页面中，正文不遮挡图片
- 导出的 PPT 打开后，正文文本框不会自动向下明显扩张

## 7. 需求二：新增知识库能力

### 7.1 目标

在 OpenMAIC 中引入知识库模块，用于管理课程相关的长期资料，并让课堂生成优先使用知识库内容，而不是完全依赖模型自由生成。

### 7.2 能力定义

知识库是一个按集合组织的教学资源池，支持：

- 创建知识库
- 编辑知识库元信息
- 删除知识库
- 导入文件到知识库
- 对知识库内容进行解析、切分、索引
- 在课堂生成中检索并引用知识库内容

### 7.3 支持的知识资产类型

`v0.1` 至少支持：

- PDF
- TXT / Markdown
- 图片
- 视频

其中：

- 文本文档用于检索增强
- 图片和视频用于教学素材复用

### 7.4 需求项

#### 7.4.1 知识库集合管理

要求：

- 支持创建、重命名、删除知识库集合
- 每个知识库至少包含：
  - 名称
  - 描述
  - 创建时间
  - 更新时间
  - 文件数量
  - 索引状态

#### 7.4.2 文件导入与元数据登记

要求：

- 上传到知识库的文件必须登记统一元数据
- 至少记录：
  - 文件 ID
  - 原始文件名
  - MIME type
  - 存储路径
  - 文件大小
  - 所属知识库
  - 导入时间

#### 7.4.3 文档解析与索引

要求：

- 文本文档导入后需要执行解析、切分、索引
- 知识库检索至少支持：
  - 关键词检索
  - 语义检索
- 当没有 embedding 模型可用时，允许回退到关键词/全文检索

#### 7.4.4 知识库搜索 API

要求：

- 提供知识库搜索接口
- 支持按知识库范围检索
- 返回结果应包含：
  - 命中文本
  - 来源文件
  - 命中分数
  - chunk / page / segment 元信息

#### 7.4.5 课堂生成接入知识库

要求：

- 课堂大纲生成、内容生成、动作生成链路应可接入知识库
- 当用户选择知识库时，生成链路必须优先引用知识库内容
- 若知识库未命中，才允许退回模型常识生成

### 7.5 验收标准

- 可创建和删除知识库
- 可向知识库导入 PDF、文本、图片、视频
- 文本型文件可被检索命中
- 生成课堂时可显式选择知识库
- 生成内容能引用知识库文本而非完全自由发挥

## 8. 需求三：新增记忆能力

### 8.1 目标

在 OpenMAIC 中新增“记忆”模块，用于沉淀长期可复用的信息，包括：

- 用户偏好
- 教学风格偏好
- 常用课堂结构
- 关键知识点总结
- 课堂生成后的高价值结论

### 8.2 记忆类型

`v0.1` 至少支持以下记忆分类：

- `preference`：用户偏好
- `teaching_rule`：教学规则
- `template`：模板
- `fact`：稳定事实
- `summary`：总结性记忆
- `general`：通用记忆

### 8.3 需求项

#### 8.3.1 记忆数据模型

每条记忆至少包含：

- 记忆 ID
- 内容
- 分类
- 关键词
- 标签
- 时间戳
- 扩展元数据

#### 8.3.2 记忆 CRUD

要求：

- 支持新增记忆
- 支持查看记忆
- 支持编辑记忆
- 支持删除记忆
- 支持列表与筛选

#### 8.3.3 记忆搜索

要求：

- 支持按关键词搜索
- 支持按语义搜索
- 支持按标签、分类过滤
- 当 embedding 模型不可用时可回退到基础文本搜索

#### 8.3.4 记忆在生成链路中的使用

要求：

- 课堂生成前可加载相关记忆
- 用户偏好、教学风格等记忆应能影响大纲与内容生成
- 生成后的高价值结论可手动沉淀为记忆

#### 8.3.5 隔离设计

要求：

- 参考 `xagent` 的 user-isolated memory 思路设计隔离层
- OpenMAIC `v0.1` 即使当前按单用户运行，也必须保留未来多用户隔离扩展点

### 8.4 验收标准

- 用户可新增、编辑、删除记忆
- 可按关键词和标签检索记忆
- 课堂生成时可选用记忆增强
- 记忆查询结果可稳定返回

## 9. 需求四：知识库支持视频导入，并在生成的 PPT 中嵌入视频

### 9.1 目标

让视频成为知识库中的正式资产来源，而非只依赖 AI 生成。

### 9.2 当前能力边界

OpenMAIC 当前已经支持：

- AI 生成视频
- 画布中渲染视频元素
- PPT 导出时嵌入视频媒体

因此本需求新增的是：

- 知识库导入视频
- 课程生成阶段引用知识库视频
- 导出 PPT 时嵌入知识库视频

### 9.3 需求项

#### 9.3.1 知识库视频文件导入

要求：

- 知识库必须支持导入常见视频格式，至少包含 `mp4`
- 上传后需登记视频元数据：
  - 文件 ID
  - 时长
  - 尺寸
  - MIME type
  - 封面图
  - 存储路径

#### 9.3.2 知识库视频预览与选择

要求：

- 在知识库中可以看到视频列表
- 支持预览视频封面与基本信息
- 在课程生成时可以选择引用知识库视频

#### 9.3.3 大纲与内容生成支持知识库视频

要求：

- 当某页内容适合使用已有知识库视频时，系统应优先复用知识库视频
- 生成的 `video` 元素来源应区分：
  - AI 生成视频
  - 知识库导入视频

#### 9.3.4 PPT 导出嵌入知识库视频

要求：

- 对知识库视频，PPT 导出应沿用现有 `addMedia` 能力嵌入
- 导出时应尽量携带视频封面
- 若视频无法嵌入，应给出明确错误或降级策略

### 9.4 验收标准

- 能向知识库导入视频
- 能在课程编辑或生成时选中知识库视频
- 导出的 PPT 中可嵌入知识库视频
- PPT 中视频具备可见封面，基础播放行为正常

## 10. 非功能需求

### 10.1 稳定性

- 知识库文件导入失败时不得破坏现有课堂数据
- 索引失败时需保留文件元数据并标记状态
- 记忆检索失败时应回退为无记忆模式，而非整链路失败

### 10.2 可扩展性

- 需为未来多用户隔离保留扩展位
- 需为未来替换向量存储或 embedding 模型保留抽象层
- 需支持未来新增更多知识资产类型

### 10.3 安全性

- 文件名和知识库名必须做路径安全校验
- 不允许路径穿越
- 删除知识库时应使用安全删除策略，避免并发误删

## 11. 版本验收总标准

`v0.1` 版本整体通过验收，至少需要满足以下条件：

1. PPT 正文导出可读，不再大面积溢出
2. 可创建知识库并导入文档与视频
3. 可创建记忆并进行基础检索
4. 课堂生成能接入知识库和记忆
5. 知识库视频可被引用并嵌入导出的 PPT

## 12. 实施优先级建议

建议按以下顺序推进：

1. 先修复 PPT 正文导出问题
2. 再落地知识库基础存储与文件导入
3. 再落地记忆模块
4. 最后打通知识库视频到课程生成和 PPT 导出的链路

原因：

- PPT 文本问题是现阶段最直接的可用性缺陷
- 知识库和记忆属于基础设施，先打底层再接生成链路风险更低
